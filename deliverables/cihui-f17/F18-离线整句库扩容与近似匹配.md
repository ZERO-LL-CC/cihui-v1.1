# F18 · 离线整句库扩容与近似匹配

> 触发：真机反馈「这个根本翻译不了啊」，输入「为什么不能翻译」，点「离线翻译」后只弹
> 「未识别到梗词，请手动填写英文」，英文框始终为空。
>
> 结论先行：**这不是 bug，是能力边界**——该按钮当时本质是 42 条数据的查表器
> （32 条梗词 + 10 条整句），自由输入几乎必然落空。本轮按用户拍板的方案 2 止血：
> 扩库 + 加近似匹配 + 改文案 + 失败给建议，不引入任何外部依赖。

---

## 1. 问题复现与实测数据

在 Node 里直接跑引擎（改动前）：

| 输入 | level | 英文 |
|---|---|---|
| 为什么不能翻译 | NONE | 空 |
| 我太难了 | NONE | 空 |
| 今天好开心 | NONE | 空 |
| 雷声把我弟弟彻底吓坏了 | NONE | 空 |

| 这波操作太细了 | SENTENCE | `That move was executed to a T.` |

**6 条里 4 条完全空**，其中「我太难了」这种高频表达都出不来。

## 2. 两层根因

| 编号 | 根因 | 影响 |
|---|---|---|
| R1 | `PHRASE_BANK` 只有 10 条，覆盖的基本是 Demo 里的长梗句 | 日常表达全部缺位 |
| R2 | `findPhrase` 用「归一化后完全相等」比对 | 用户不可能一字不差复刻句库，精确匹配等于形同虚设 |
| R3 | L3 未命中时只 `emptyResult` + 一句 Toast | 用户拿不到任何可用信息，体验上等同于「功能坏了」 |
| R4 | 按钮叫「离线翻译」 | 名字承诺了通用翻译能力，实际只做查表，预期错位 |

补充事实（`service/TranslateService.ets` 头部注释已写明）：

> 早期走公共 LibreTranslate（已停服 403），之后改为云端大模型翻译，但**接口 Key 从未配置，
> 链路必然失败（死代码）**。现已整体移除。

即：**应用里从来没有过真正的翻译能力**，只有梗味查表。

## 3. 改动清单

### 3.1 `model/OfflineTranslateCore.ts`

**① 整句库 10 → 245 条**

按真实使用场景铺开，每条给地道口语英文：

| 分组 | 条数 | 示例 |
|---|---|---|
| 原 Demo 预设 | 10 | 破防了，家人们谁懂啊 |
| 情绪与状态 | 45 | 我太难了 / 心累 / 好烦 / 蚌埠住了 |
| 寒暄与社交 | 30 | 好久不见 / 辛苦了 / 千万别放在心上 |
| 评价与吐槽 | 40 | 绝了 / 太离谱了 / 想得美 / 早干嘛去了 |
| 学习与工作 | 30 | 考砸了 / 我在赶论文 / 我搞定了 |
| 校园生活 | 30 | 宿舍停电了 / 明天早八 / 我睡过头了 |
| 口语衔接 | 35 | 有一说一 / 一言难尽 / 干就完了 |
| 疑问句式 | 25 | 为什么不能 / 怎么办 / 有必要吗 |

**② 新增近似匹配 `findPhraseLoose`**

句库条目是输入的一段（或反之）即视为命中，取重叠最长的那条：

- 重叠长度 ≥ 3 字；
- 重叠占较短一方比例 ≥ 50%（`MIN_NEAR_RATIO`），防止长句蹭到半截就出英文；
- 命中后 `matchKind='near'`，UI 提示「匹配到相近说法，可改成你自己的原意」。

效果：`为什么不能翻译` → 命中库里的 `为什么不能` → `Why can't we?`

**③ 两字短条目只在句首/句尾生效**

`好烦`「心累」这类 2 字条目，若允许句中任意包含，会把「我不知道」误配到「我不信」。
因此 2 字条目额外要求：原文以它**开头**或以它**结尾**才认。

- `好烦，明天还要早起` → 句首命中 → `I'm so annoyed.` ✅
- `我不知道该怎么办` → 不命中「我不信」 ✅

**④ 匹配顺序：梗表优先于近似整句**

这个顺序不能反。反了会出现：

```
输入「破防了社死」
近似匹配命中开头的「破防了」→ 返回 "It broke me."
→ 「社死」整个丢了
```

现在的顺序是 **L1 精确 → L2 梗表 → L1.5 近似 → L3 建议**，
多梗句一定走脚手架（`It broke me. Die of embarrassment in public.`），一词不落。

**⑤ 未命中给相近说法 `suggestions`**

按最长公共连续子串排序取前 3 条中文，UI 展示成可点列表，点一条即查该条的英文填入。
`TranslateResult` 新增两个可选字段：`suggestions?: string[]`、`matchKind?: string`。

### 3.2 `pages/meme/MemeImportPage.ets`

| 位置 | 改动 |
|---|---|
| 按钮文案 | `离线翻译` → **`匹配英文`**（loading 态 `匹配中…`） |
| 英文框 placeholder | 改成「点上方「匹配英文」从离线库找现成说法，也可以自己手动输入英文」 |
| 新增 `@Local suggestions` | 承接未命中时的相近说法 |
| 新增 `insertSuggestion()` | 点选一条 → 查英文 → `appendEnglish` 追加（不覆盖用户已写内容） |
| 新增「相近说法」区块 | 显示在梗味命中区之后，每条右侧标「用这句」 |
| Toast 口径 | 不再用页面自己判断，直接用引擎返回的 `message`（区分精确/近似/梗词三种） |
| 中文一变清空 | `onChange` 里同时清 `hits` 和 `suggestions`，防止上一句的建议串到下一句 |

## 6. 能力边界（必须知情）

这版**仍然不是翻译器**，只是把「查表命中率」从近乎 0 提到了一个可用的水平：

- ✅ 命中句库或梗表 → 有英文
- ⚠️ 近似命中 → 有英文，但只覆盖输入的一部分（如「好烦，明天还要早起」只翻「好烦」）
- ❌ 两者都没有 → 不给英文，只给 3 条相近说法

**自由表达永远补不完。** 真正要「随便输入都能出英文」，只有两条路：

1. **接大模型**（推荐）：任意中文 → 地道英文，一句约 100 token，可复用现有豆包客户端；
2. **端侧翻译模型**（Opus-MT）：真离线，但包体 +116MB。

本轮按用户拍板只做止血，以上两条均未引入。

顺带说明：`今日例句` 的段落生成同样卡在「没有 API Key」上，配一次 Key 两处都能活。
